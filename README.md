# dsh-plugin-compat-check

检查**已安装的DSH插件**与目标版本的兼容性，提供源码位置、依据和覆盖限制。声明放行、激活或无发现不等于业务正常。欢迎 [Star ⭐](https://github.com/lcy0121/dsh-plugin-compat-check)。

**简体中文** | [English](README.en.md) | [한국어](README.ko.md)

## 版本与入口

**0.1.7** 提供rc.3适配、升级预检、参数语义与边界加固。Node `^22.19.0 || >=24`，宿主声明 `>=0.2.0-rc.2`；已认证精确目录仅 **0.2.0-rc.2、0.2.1-rc.2、0.2.1-rc.3**，最低版本声明不认证未来宿主。

npm插件提供兼容性页、详情/角标、`compat_check`与skill。仓库另有CLI、安装检查、静态批量、作者CI和健康执行器，共享内核。npm包无CLI bin，不支持`npx dsh-plugin-compat-check`。[Plan](docs/Plan.md)维护契约与待办，[docs/current-state.json](docs/current-state.json)记录限定验证。

## 安装与使用

```bash
dsh plugin --profile <profile> add dsh-plugin-compat-check
```

安装后，在使用该profile的DSH主界面中打开：

**左下角“更多”（⋯）或用户头像（账号菜单） → 设置 → 内置插件 → 兼容性**。

“更多”指左下角的账号入口；进入“内置插件”后选择“兼容性”页签。请确认正在使用安装本插件的profile，不默认是desktop。agent也可调用`compat_check`。

### 界面各板块怎么用

以下按仓库中**尚未发布的0.1.8开发界面**说明；已发布0.1.7的布局和按钮可能不同。

界面支持**中文、English、한국어**，默认跟随宿主语言；主结果标题旁的“界面语言”可切换或恢复“跟随宿主”，偏好仅保存在本机本插件中，不修改宿主语言。未支持的宿主语言回退英文。按钮、状态和无障碍标签随语言更新；故障报告的标题、说明和核实建议跟随界面语言，复制与预览一致；原始发现、诊断、人工依据及JSON导出保留原文，切换语言不会重置筛选或草稿。

常用顺序为**主结果 → 依赖关系 → 人工处置 → 升级预检**；低频操作统一放在默认收起的“高级工具”。

| 板块 | 用途与操作 |
|---|---|
| **兼容性检查（主结果）** | 先看结论、检查对象/目标DSH、报告时间和缓存状态，点“重新检查”更新。搜索并组合结论/确定性/验证状态筛选，展开该行的发现、覆盖限制及下一步核实。主表每页50行；框内“预览故障报告”提供完整文本，核对敏感信息后复制并自行分享，筛选/分页不删减导出；“报告与证据说明”按需展开。 |
| **依赖关系与潜在影响** | 按需展开插件/loader条目、服务依赖、候选提供者和影响路径等表格，每页50行。声明、loader状态及路径只是排查线索，不证明服务可用或实际故障传播。 |
| **发现的人工处置** | 从发现旁“核实与人工处置”定位编辑区，选择人工状态、填写依据并保存；用于分批排查、追踪误报及修复验证。只想看当前结果时可以跳过。 |
| **升级前兼容性预检（静态）** | 展开后输入目标DSH精确版本，再点“运行升级预检”。仅做静态预测，不安装或升级DSH；无新增风险不代表业务通过。 |
| **高级工具（默认收起）** | 按需展开后使用“人工处置记录管理”加载容量/归档，“本地历史报告与趋势”保存及对照更新前后快照，或导入外部“功能健康检查”JSON。记录功能和显式导出/删除仍保留；不会自动采集历史、运行健康检查、安装插件或上传记录。 |
| **报告说明与检查信息（页尾折叠）** | 展开查看工具版本、采样与对象来源。确定性、实测/推断说明移入主结果中的“报告与证据说明”；目录身份仍在主结果核对，未认证警告直接显示。 |

辅助大表默认收起，点带文字的“展开/收起”按钮切换；内容滚入视区时按需加载，窄容器内的大表可横向滚动。插件详情中的结论/角标用于查看单个插件，完整列表和筛选位于上述“兼容性”页。

单插件发现、预检风险分组、两版本插件明细及输入制品也按每页50项浏览；新增/变重风险仍默认展开，其他只读明细按需展开，翻页不截断完整导出。界面沿用宿主登录会话；出现身份校验提示时，请重新打开宿主给出的登录入口，勿把登录链接或Cookie附在报告中。

“本次新增风险”依赖可比较的历史记录；首次检查或覆盖不完整时可能尚无记录，这不表示没有风险。“可用”且“无已验证调用”也不等于业务已验收。

### 人工处置的填写示例

1. 在主结果中展开一条发现，按其位置和“下一步核实”检查实际情况。
2. 在主结果展开某条发现后点**“核实与人工处置”**，直接定位对应编辑区；也可用“筛选处置插件”和“筛选人工状态”查找。每条显示类别、API、源码位置及已保存依据摘要，点“返回主结果”可清除主表筛选并跳转到对应页和发现。关联按报告/发现身份保持，不依赖当前排序或页码。选择**待确认 / 已复核 / 误报 / 已修复**，填写“核实依据”。例如，确认误报后写明测试步骤、实际表现和原因；修复后写明改动与复测结果。“已复核”只表示人工检查过，不自动表示通过。
3. 点**“保存人工处置”**，看到“人工处置已保存”才表示记录成功。条目较多时点“显示更多处置”；筛选不会隐藏未保存草稿，也不会隐藏主结果中的风险；需要回溯时展开旧处置摘要或“历史处置完整依据”。

未保存的输入在当前页面会话中作为草稿保留。后台刷新改变报告身份时，旧草稿会标为“草稿已过期”并禁止保存到新发现；可点“复制草稿”，在当前发现中重新核实后填写并保存，或点“放弃草稿”。同一报告的记录更新不会清空正在填写的依据。刷新网页、离开页面或卸载插件前，请先保存或复制；草稿不写入磁盘。

记录保存在本机，供后续排查参考；源码、版本或证据变化后可能显示“待重审”，旧依据保留为历史。**标记误报或已修复不会隐藏发现、修改兼容性结论/退出码/基线，也不授予豁免**；更新代码或配置后应重新检查。只想看本次结果时，可以跳过人工处置。

先展开“高级工具”，其中“人工处置记录管理”默认收起。先点“加载处置容量与归档”；活动文件仍限1 MiB/1000条。“归档历史处置”保留当前已保存状态，“归档全部处置”也移走当前状态，均需再次确认，并先保留完整备份。每个目标最多100份归档，满后需预览导出并显式移除；不会静默清理。查看/恢复或导入的归档只作参考，可复制旧依据、核实当前发现后重新保存。

“高级工具”中的“本地历史报告与趋势”默认收起且不后台采集。填写快照备注，分别在更新前后点“保存当前报告快照”；以后点“加载历史报告”检索，选起点/终点后点“对照两份历史报告”。同一目标、DSH、工具、采样方式、规则和目录才作方向比较；身份不同可展开两份完整报告并列核对，证据减少不称修复。每个目标最多20份、合计64 MiB、单份8 MiB，满后须导出并显式移除。导出先预览再下载，包含路径与依据，分享前检查敏感信息。摘要只是完整性校验，不是签名；历史不认证当前目标，也不证明业务健康。


[使用指南](docs/guide.md)提供详细操作、证据边界和预算。

## 仓库CLI

仓库工具从源码运行：

```bash
git clone --branch main https://github.com/lcy0121/dsh-plugin-compat-check.git
cd dsh-plugin-compat-check
npm ci --ignore-scripts
node bin/compat-check.mjs --nm ~/.dsh/profiles/<profile> --no-baseline
node bin/compat-check.mjs --help
```

| 选项 | 作用 |
|---|---|
| `--nm <dir>` | 目标profile或node_modules；必需 |
| `--dsh-version <v>` | 目标DSH版本；预检中为当前版本 |
| `--probe <json>` / `--probe-boot` | 读取观测 / 经授权启动临时宿主 |
| `--json` / `--quiet` | 完整JSON / 总结行 |
| `--no-baseline` / `--dry-run` | 禁读写基线 / 比较但不写 |
| `--baseline-file <path>` | 自定义基线位置 |
| `--issue-report` | 可分享Markdown；预览后自行分享 |
| `--rules <json>` / `--catalog <json>` | 覆盖规则 / 参考目录 |
| `--help` / `--version` | 完整帮助 / 工具版本 |

静态检查不执行目标或联网，普通检查写自身基线；no-baseline禁读写，不完整扫描不推进。probe-boot/安装检查会执行目标，须相应授权；临时profile不是OS沙箱。

## 升级预检与作者工具

面板输入目标版本，或调用`compat_check({"upgradeTo":"0.2.1-rc.3"})`；agent当前版本取宿主，结果为`upgradePreview`。CLI须提供两个精确版本：

```bash
node bin/compat-check.mjs --nm ~/.dsh/profiles/<profile> --dsh-version 0.2.1-rc.2 --upgrade-to 0.2.1-rc.3 --json
```

三个精确版本可任意比较，未知版本退出3。只静态比较同组私有字节，不升级/执行宿主或借用probe、豁免、普通基线。**0/1/2表示无/非致命/致命新增或变重风险，3表示无法预检**；0仍可有旧风险。见[契约](docs/Plan.md#27-升级前静态预检契约)。

[作者CI](docs/author-ci.md)提供矩阵、门禁及JSON/SARIF/JUnit/HTML；[指南](docs/guide.md#升级预检与有限批量)提供静态批量。健康执行器默认review，run须授权。另见[skill](skill/README.md)与[完整tgz构建](plugin/README.md#从源码构建安装)。

## 结果与验证

普通退出码：**0未发现冲突、1部分可用或未知、2不兼容、3工具/输入错误**。保留certainty/impactBasis/coverage/vacuous，未观测不是缺失；坏基线保留原件。客户端业务另验收，分享前预览，导出不自动发帖。

```bash
npm test
npm run check
node plugin/scripts/prepublish-check.mjs
node tools/meta-check.mjs --json
```

默认测试不启动真实DSH/模型，打包回归需要registry；`check`核对格式、文档/生成副本、语法与目录。发布前检查不发布；元数据核验需gh/npm和网络，取数失败不算通过。macOS/Linux仅有记录范围内证据，Windows未真实验收。
